# 포트폴리오 읽기 흐름과 페이지 구성 수정

2026-11-18. 본문과 지원 회사별 선별은 그대로 유지한다. 모바일은 범위 밖이다.

## 확인한 원인

- 모든 설명 페이지가 같은 좌우 2열을 사용해 화면 아래 공간을 활용하지 못했다.
- 긴 실행 화면에 `object-fit: cover`를 적용해 원본 일부가 잘렸다.
- 버튼만으로 이동하고 휠로 넘길 수 없어 문서를 빠르게 읽기 어려웠다.
- 참고 PDF는 소개, 단계, 기술 비교, 기능 화면, 문제·해결·검증에 서로 다른 구성을 사용한다.

## 변경

1. 원문 보존 검사와 기존 경로·탭·확대·목차 검사를 유지한다. 휠 누적 입력·관성·고정 시간·방향 전환 및 내부 스크롤 경계를 검증하는 회귀 검사를 먼저 추가한다.
2. 소개는 본문과 지표, 사용자 흐름은 단계와 설명, 기술은 비교 영역, 기능은 실제 화면 아래 설명, 사례는 한 장에서 문제·선택과 해결·검증·결과를 함께 읽도록 구성한다. 관련 없는 화면을 모든 사례에 반복하지 않는다.
3. 이미지는 원본 비율을 유지한다. 작은 데스크톱 창에서는 한 페이지 전체가 세로로 이어지고, 그 페이지의 마지막까지 읽은 다음 새 휠 동작으로 다음 페이지를 연다.
4. 휠 한 동작은 한 장만 이동한다. 이동 뒤 고정 시간과 관성 입력 종료를 확인한다. 목차·확대창·이력서·Ctrl 확대에는 개입하지 않는다. 버튼과 방향키는 보조 조작으로 남긴다.
5. 960/1280/1440/1920/2560px 데스크톱 창, 실제 휠 입력, 원문 보존, PDF 글자·경계, 빌드·타입 검사 후 배포한다. 검증 수치와 구현 수치를 혼동하지 않는다.

## 검토 분리

구현은 주 에이전트가 담당한다. 독립 탐색 에이전트는 기존 선택의 원인과 회귀 검사 범위를 읽기 전용으로 검토한다. 기존 이력서의 구조와 파일 트리의 모양은 유지한다. 새 의존성은 추가하지 않는다.

## 로컬 검증

- 휠 제스처 단위 검사, 엄격한 TypeScript 검사, Vite 빌드 통과.
- 7개 데스크톱 크기에서 공통10장·회사17장 전체를 순회하고 총29개 브라우저 검사 통과. 960×700 읽기 경계, 실제 wheel 입력과 합성 관성 입력, 방향 전환·확대·목차·다운로드·기존 경로 포함.
- 전환 직후 새 페이지 본문이120px 움직이는 회귀를 재현한 뒤0px로 수정했다. 이는 포트폴리오 뷰어 자체의 회귀 검사이며, 모아 프로젝트의 성능 지표와 관계없다.
- PDF는 공통10장·회사17장·기존 이력서2장. 본문 원문 단위123/244/47개 누락0, 글자 수 감소0, 주요 본문13.5pt, 용지 밖 잘림0. 기존 이력서는 내용·양식·PDF 바이트를 보존했다.
- 실제 물리 마우스·트랙패드의 장치별 감도와 모바일은 검토하지 않았다. 자동 브라우저 wheel 입력으로 동작을 검증했다.
