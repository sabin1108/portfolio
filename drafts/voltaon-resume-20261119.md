### 나뉘거나 합쳐져 도착하는 SSE 데이터를 처리하는 문제

**수신 버퍼와 SSE 파서**로 완성된 이벤트만 해석하고, 남은 조각은 다음 수신까지 보관했습니다. 형식·순서를 확인한 뒤 본문·완료·오류 상태에 반영했습니다.

### 응답 완료 시 남은 글자가 한꺼번에 표시되는 문제

**수신 본문과 표시 길이를 분리**해, 응답이 끝나도 requestAnimationFrame에 맞춰 남은 글자를 이어서 표시했습니다. 중지·오류 시 남은 표시 작업도 정리했습니다.

### 취소한 요청의 늦은 결과가 현재 화면을 바꾸는 문제

작업을 취소한 뒤에도 늦게 도착한 결과 때문에 화면이 완료 상태로 바뀔 수 있었습니다. 취소 여부와 현재 진행 중인 요청이 맞는지 다시 확인했습니다. 화면 반영과 저장 직전에도 다시 검사해 이전 요청의 결과를 적용하지 않도록 했습니다.

### 폴더 이동 중 입력창과 목록이 깜빡이는 문제

폴더 이동 시 입력창과 기존 목록을 유지하고 새 목록이 준비되면 내용만 교체했습니다. 로딩 중 확정·생성을 막았습니다. **검사 단계 창의 상단 위치 변화는 76.27px → 0px**로 줄었고, 입력 DOM도 더 이상 제거되지 않았습니다.

*Chromium 실험 · 14개 상호작용을 각 350ms 프레임 관측*

### 파일 구조가 재사용성과 유지보수에 어려운 점을 보고 개선한 문제

**app**에는 화면 조립, **features**에는 기능별 화면·상태·규칙, **components/ui**에는 공통 부품을 두었습니다. 목적지 탐색·경로 입력·생성 폼은 조합해 재사용하고, 충돌 처리와 원본 보존 규칙은 각 작업에서 관리했습니다.

### 공통 폼의 식별값 충돌로 경로 입력이 잘못 연결되는 문제

목적지 선택 화면에는 **기존 폴더를 찾아가기 위한 경로 입력창**과 **새 파일·폴더의 이름을 입력하는 생성 폼**이 있었습니다. 두 폼을 배치하는 상위 화면에서 현재 폴더 경로만 React key로 지정해, 역할이 다른 두 폼에 같은 값이 들어갔습니다. 기존 경로값 앞에 **경로 입력용·새 항목 생성용이라는 역할을 추가**해 서로 다른 key를 지정했습니다.

### 캐시가 있어도 PDF 본문을 매번 다시 추출하는 문제

파일 내용과 추출 조건을 먼저 확인하고, 같으면 **IndexedDB의 PDF 본문을 재사용**했습니다. 원본 미변경·Worker 재사용 조건에서 중앙값은 **1쪽 82.95ms → 1.05ms, 24쪽 103.75ms → 1.25ms**였습니다.

*반복 추출 비교 · 원본 미변경 · 상위 Worker 재사용 · 최초 추출 비용과 구분*

### 길게 누른 뒤 목록이 바뀌어 다른 파일이 열리는 문제

파일을 길게 누르면 선택 모드로 바뀌면서 목록이 밀렸고, 손을 떼는 순간 다른 파일이 열리는 문제가 발생했습니다. 이를 해결하기 위해 **선택 모드로 전환된 직후 발생하는 클릭을 한 번 차단**하고, 선택 표시가 나타나도 목록이 밀리지 않도록 행 높이를 유지했습니다.
