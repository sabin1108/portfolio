### 폴더 이동 중 입력창과 목록이 깜빡이는 문제

폴더 이동 시 입력창과 기존 목록을 유지하고 새 목록이 준비되면 내용만 교체했습니다. 로딩 중 확정·생성을 막았습니다. **14개 상호작용의 각 350ms 관측에서 입력 DOM 제거 0회**를 확인했습니다.

### 취소한 요청의 늦은 결과가 현재 화면을 바꾸는 문제

**AbortController**로 취소한 뒤에도 늦게 돌아온 결과가 현재 화면을 바꿀 수 있어, 취소 여부와 현재 요청의 식별값을 함께 확인했습니다. 화면 반영과 저장 직전에도 다시 검사해 이전 요청의 결과를 적용하지 않도록 했습니다.

### 파일 구조가 재사용성과 유지보수에 어려운 점을 보고 개선한 문제

**app**에는 화면 조립, **features**에는 기능별 화면·상태·규칙, **components/ui**에는 공통 부품을 두었습니다. 목적지 탐색·경로 입력·생성 폼은 조합해 재사용하고, 충돌 처리와 원본 보존 규칙은 각 작업에서 관리했습니다.

## 2페이지

### 공통 폼의 식별값 충돌로 경로 입력이 잘못 연결되는 문제

두 폼은 같은 폴더 위치를 사용하지만, 하나는 **기존 위치로 이동**하고 다른 하나는 **새 항목을 생성**합니다. 현재 경로만으로는 서로 다른 두 폼을 구분할 수 없으므로, key에 각 폼의 역할도 포함해야 한다고 판단했습니다.

### 설정을 다시 열 때마다 같은 정보를 기다리는 문제

자주 바뀌지 않는 설정 표시 정보는 **Next.js Data Cache**로 사용자·로그인별로 재사용하고, 정보가 바뀌면 갱신했습니다. 현재 인증과 작업 권한은 매번 확인했습니다. 로컬 production의 반복 설정 진입 **36표본**에서 준비 중앙값은 **1.541초 → 0.675초, 약 56.2% 감소**했습니다. 초기 준비 비용은 별도로 구분했습니다.

### 길게 누른 뒤 목록이 바뀌어 다른 파일이 열리는 문제

파일을 길게 누르면 선택 모드로 바뀌면서 목록이 밀렸고, 손을 떼는 순간 다른 파일이 열리는 문제가 발생했습니다. 이를 해결하기 위해 **선택 모드로 전환된 직후 발생하는 클릭을 한 번 차단**하고, 선택 표시가 나타나도 목록이 밀리지 않도록 행 높이를 유지했습니다.
